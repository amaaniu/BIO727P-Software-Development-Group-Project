# Workflow

This section documents the core end-to-end portal workflow.

## 0. Complete a DE experimental cycle (laboratory stage)

Before upload, a DE cycle is performed in the laboratory:
- Variant libraries are generated by mutagenesis.
- Variants are screened and selected based on assay performance.
- Top-performing variants are carried forward to the next generation. This is usally quantified using DNA and protein abundance.

Selected droplets/variants are then profiled, sequenced, and prepared for upload to the portal.

## 1. Register experiment in the portal

Create an experiment record and provide:
- Target protein name.
- UniProt accession.
- Optional campaign notes.

Expected system behaviour:
- Portal fetches wild-type sequence and relevant annotations.
- Metadata is stored for downstream validation and analysis.

## 2. Upload plasmid FASTA and run datasets

Upload:
- plasmid FASTA data for the selected variants;
- run data files (`.tsv` or `.json`) containing assay outputs and identifiers.

Expected system behaviour:
- File format and schema are checked.
- Required columns/keys are validated.
- Record counts and missing values are summarised.

## 3. Validate sequences and measurements

Run validation checks before scoring.

Typical checks:
- Invalid characters in sequences.
- Length mismatch against expected target region.
- Missing activity values.
- Outlier or impossible values based on assay constraints.

## 4. Run analysis

Start the analysis pipeline to produce:
- Activity Metric per variant 
- Ranked variants table.
- Generation/round-level summary statistics.

## 5. Review and export outputs

View the results, export them as a .pdf or .png:
- Filter top variants.
- Compare across rounds.
- Export result tables for reporting.
