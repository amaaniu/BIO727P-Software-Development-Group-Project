# Workflow

This section documents the core end-to-end portal workflow.

## 0. Complete a DE experimental cycle (laboratory stage)

Before upload, a DE cycle is performed in the laboratory. Variant libraries are generated by mutagenesis, screened based on assay performance, and the top-performing variants are carried forward to the next generation. This is usually quantified using DNA and protein abundance.

The droplets/variants are then profiled, sequenced, and prepared for upload to the portal.

## 1. Register experiment in the portal

Create an experiment record and provide a UniProt accession ID.

Expected system behaviour: the portal fetches relevant data on the wild-type protein, and an AlphaFold model of the protein appears.

## 2. Upload plasmid FASTA and run datasets

Upload plasmid FASTA data for the selected variants and run data files (`.tsv` or `.json`) containing assay outputs and variant identifiers.

Expected system behaviour: file format and schema are checked, required columns/keys are validated, include `generation`, `plasmid_variant_index`, `dna_sequence`, `protein_yield`, `dna_yield`, `protein_sequence`, `activity_score`, `mutation_count`, and `parent_variant_id`. This website has flexibility built in it for the column names (and spelling of the names) so it does not have to be exactly this.

## 3. Validate sequences and measurements

Run validation checks before scoring.

Typical checks include detecting invalid characters in sequences, verifying that the provided UniProt ID matches the wild-type reference, confirming polymerase DNA is encoded by a plasmid, and identifying missing activity values.

## 4. Run analysis

Start the analysis pipeline to produce Activity Scores, a ranked variants table, generation/round-level summary statistics, and mutation tracking.

## 5. Review and export outputs

View the results and export them as a `.pdf` or `.png`. Users can highlight top performing variants, compare activity across rounds, and export visuals for reporting.
